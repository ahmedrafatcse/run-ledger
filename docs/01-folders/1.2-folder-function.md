# Package Overview

The following table describes the purpose of each package in the `com.runledger` namespace, its Spring Boot responsibility, the closest MERN equivalent, and why it exists in RunLedger.

| Package | Role in Spring Boot | MERN Equivalent | Why RunLedger Needs It |
|---------|---------------------|-----------------|------------------------|
| **`controller`** | Handles HTTP requests, extracts parameters, calls services, and returns responses. | Express route handlers (`app.get()`, `app.post()`) | Keeps the HTTP layer thin by handling only request parsing and response formatting. |
| **`dto`** | Simple data carriers (Java records/classes) that define request and response bodies. | Joi/Zod schemas or plain JavaScript objects from `req.body` | Separates the API contract from the database model and prevents JPA entities from being exposed directly. |
| **`entity`** | JPA-annotated classes mapped directly to database tables. | Mongoose models/schemas | Represents the relational database schema in Java and manages ORM mapping. |
| **`repository`** | Interfaces providing CRUD operations and custom queries through Spring Data JPA. | Mongoose model methods (`find()`, `save()`, etc.) | Provides type-safe, declarative database access without SQL boilerplate. |
| **`exception`** | Global exception handling using `@ControllerAdvice`. | Express error-handling middleware (`err, req, res, next`) | Returns consistent, structured JSON error responses across the application. |
| **`config`** | Spring `@Configuration` classes for application setup (security, Jackson, beans, etc.). | `config.js` files + middleware setup (`cors()`, `helmet()`, `express.json()`) | Centralizes framework configuration and infrastructure wiring. |
| **`model`** *(optional/current)* | Domain models that may not be persisted directly. May eventually merge into `entity`. | Mongoose models or plain JavaScript domain objects | Placeholder package for non-persistent domain objects; may be removed as the project evolves. |
| **`service`** | Contains business logic (hash chain generation, ingestion workflow, integrity verification). | Service layer (often merged into controllers in small MERN projects) | Keeps business logic independent from controllers and database access. |
| **`security`** | Spring Security components such as JWT providers, authentication filters, and API-key validation. | JWT middleware / Passport.js | Encapsulates authentication and authorization logic in one place. |
| **`specification`** | Reusable JPA `Specification` classes for building dynamic database queries. | Mongoose query builder helpers (`$and`, `$or`, etc.) | Enables flexible filtering without writing large native SQL queries. |
| **`util`** | Stateless helper classes (hashing, JSON utilities, formatting, etc.). | Utility modules (`hash.js`, `dateUtils.js`) | Provides reusable framework-independent helper functions that are easy to test. |

## Layered Architecture

```text
Client
   │
   ▼
controller
   │
   ▼
service
   │
   ├──────────────► util
   │
   ├──────────────► specification
   │
   ▼
repository
   │
   ▼
entity
   │
   ▼
PostgreSQL

config      → Configures the application
security    → Protects the application
exception   → Handles errors globally
dto          → Defines the API contract
```
